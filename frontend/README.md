# StarFabric 120 星前端

本地中文任务控制台，支持持续实时运行与历史验收回放。使用 Python 标准库启动服务，前端使用浏览器原生 JavaScript、Canvas、WebGL 和 SVG；日常运行不需要 Node、npm、前端构建或外部 CDN。

## 启动

在工程根目录执行：

```bash
python3 frontend/server.py
```

打开 **http://127.0.0.1:8090**。使用 `--port 8091` 可更换端口，前台启动时按 Ctrl+C 停止。

默认进入实时模式，可从界面启动独立后台服务；也可先运行 `make live-start`。完整说明见 [持续运行手册](../lab/live/README.md)。右上角“历史”切换到已完成的验收记录，其中 `sf-unified-d180f84868`：124 个 FRR 节点、120 个星上实例、31 帧物理记录、10 次改路和 872 份证据。历史结果不会显示成当前在线服务。

启动期间显示主阶段、Kubernetes 子步骤、镜像与目标节点、操作耗时和超时上限。后台每 5 秒采集本轮容器数量、节点 Ready、Pod 就绪数／等待原因／重启次数和 Warning 事件；页面每 3 秒刷新，并分别显示“最近诊断采集”和“最近步骤进展”。运行后可在“实时控制器 → 查看本轮启动诊断”中查看完成记录或导出 JSON。

自动刷新在原页面上更新变化的内容，保留地球画布、拖动操作、输入焦点和日志滚动位置，不重新播放整页淡入动画。地球只在新轨道样本或交互变化时重绘。

说明、状态栏、表格、按钮等原有 7～13 px 小字已调整为两倍字号；大标题和主要统计数值保持原来的大小。窄屏自动换行、折叠为单列，表格在自身区域内横向滚动。顶部保留模型时间、网络应用时间及异常提示，移除了“样本距今”文案。

### 地球与太阳视图

- 本地 NASA 地表与夜间灯光贴图，加上昼夜光照和大气边缘；地表旋转使用轨道帧的 GMST，与网关坐标一致。
- 卫星使用固定屏幕大小的白色亮点和深色描边，避免与地表混色；网关为金色菱形，主路卫星带金色圆环，选中或悬停时显示蓝色外环与深底标签。轨道和普通链路弱化，让节点更醒目。
- 时间与太阳信息放在画布上方，图例和操作说明放在下方，放大的文字不遮挡地球；自动刷新继续保留视角、缩放和拖动。
- 滚轮、右侧加减按钮、手机双指支持 **0.5～6 倍**缩放。拖动旋转，右上角展开按钮进入全屏；再次点击或按 Esc 退出。重置按钮恢复初始视角。
- 太阳方向与日地距离按**当前模型时刻**近似计算，历史回放也使用该帧时间。地球光照采用同一太阳方向。太阳在画外、被地球遮挡或接近视线轴时显示方向提示，点击右上角太阳卡片恢复日地视角。
- 太阳大小与日地距离经过示意压缩，方便同屏观察；距离卡片的 AU 值是计算值，1 AU 约 1.496 亿公里。历史地表与夜光影像不代表实时天气或城市状态。来源、署名及坐标近似见 [影像来源](assets/CREDITS.md)。
- 不支持 WebGL 时使用 Canvas 软件绘制地表和昼夜，自动降低绘制分辨率以保持可操作。

| 星上自治 | 全部 120 个实例的失联接管／最终恢复快照切换；逐星真实状态和备用下一跳 |
| 协议与承载 | 六种承载的作用、实际检查和报文证明；明确完整故障矩阵是否通过 |

### 实时连接

将地址替换为实际控制器地址：

```bash
python3 frontend/server.py --controller http://127.0.0.1:8080
# 控制器启用 Bearer token 时：
python3 frontend/server.py --controller http://127.0.0.1:8080 \
  --controller-token-file /path/to/token
```

上述 `--controller` 用于历史模式中的额外只读接入，每 10 秒读取四个 GET 接口。完整常驻模式使用 `make live-start`，所有主页面每 3 秒获取本轮实时状态。未配置或控制器不可达时显示离线。TLS 使用 Python 默认验证。

## 数据和文件分工

```text
reports/physical-platforms + reports/platforms + lab/unified/artifacts
    → server.py：实时 / 历史数据 API 与本地常驻服务的启动、停止入口
    → app.js：页面、筛选、回放、证据与配置交互
    → globe.js：TEME 轨道、链路、太阳标记、相机和缩放交互
        → solar.js：模型时刻 → 近似太阳方向与日地距离
        → earth-surface.js + assets/：地表、夜间灯光与太阳光照
    → style.css：响应式布局与视觉
```

- `/api/dashboard?run=<run_id>`：运行、模型、帧、已提交路径、自治、报文、文件与功能目录。
- `/api/file?path=<工程相对路径>`：允许的工程学习文件和运行证据；加 `download=1` 下载。
- `/api/dashboard?mode=live`：当前常驻星座的轨道、计划、业务、星上状态；未就绪时返回明确的启动阶段。
- `/api/runtime`：服务阶段；`POST /api/runtime/start`、`POST /api/runtime/stop` 仅接受同源 JSON 固定操作。
- `/api/live`：历史模式下读取启动参数中另行配置的控制器。
- `/healthz`：展示服务健康检查。

服务仅绑定 `127.0.0.1`，文件路径必须位于项目及允许范围内；不提供命令执行或任意文件浏览。

## 解释边界

- 物理专项通过与完整协议矩阵通过分别展示。独立专项通过不能合并成全系统统一通过。
- 卫星位置来自物理模型记录的 TEME 坐标；地球使用历史遥感贴图，太阳为日期赤道坐标近似方向。这是模型态势展示，不是卫星实测遥测或导航星历。节点详情的经纬度是地心近似转换。
- 每帧保留最近一次实际提交的路由；新帧未改路时不会编造新提交。新观测拓扑版本与提交版本分别列出。
- RTT 曲线读取 `continuous-ping.log`；每星 PCAP 计数可能包括同包不同接口的观测。
- 配置编辑只导出副本，不修改工程输入，也不重新运行轨道传播。导出的配置仍需运行物理生成器和路径预检查。
- 实时模式可启动、停止整套常驻系统，自动更新轨道、链路和路由。故障注入、协议矩阵和升级验收继续使用原工程专项入口。
- 120 星失败运行如果缺少归档轨道，会显式使用已有生成配置做预览，保持失败结果和部署数量原样。

## 验证

后端契约和数据核对（只读取现有证据）：

```bash
python3 -m unittest frontend.test_server -v
```

浏览器验收需要单独的测试依赖，不影响日常启动：

```bash
python3 -m venv /tmp/starfabric-ui-test
/tmp/starfabric-ui-test/bin/pip install playwright
/tmp/starfabric-ui-test/bin/python -m playwright install chromium
/tmp/starfabric-ui-test/bin/python frontend/browser_check.py
```

浏览器检查会临时启动自己的本地展示服务，验证全部页面、节点与文件详情、回放、路由、自治阶段、协议范围、下载、配置校验、全局搜索和手机布局。测试报告与截图保存在 `reports/frontend/`。

`frontend/startup_browser_check.py` 使用 8090 上的展示服务，并在测试浏览器内替换启动 API 响应，检查等待、失败、诊断过期、接口断开、日志阅读位置、导出和手机布局；不启动或停止真实集群。`frontend/live_browser_check.py` 则读取已运行的真实星座，并检查启动记录在运行后仍可查看。

`frontend/globe_browser_check.py` 同样只读运行中的 8090 服务，检查地表加载、太阳季节位置、方向光照、地球遮挡提示、6 倍缩放、跨刷新保留画布、全屏、手机双指和无 WebGL 降级；输出 `reports/frontend/globe-browser-check.json` 及 `earth-*.png`。

“业务”与“协议”页按当前实例显示并行 TCP/UDP 业务：分别显示控制方式、承载、配置速率、有效速率、RTT 和卫星抓包证据。在线调速接口只接受当前运行标识和 0.1–1 的比例，控制器保留配置上限对应的容量预留。未启动新增业务的旧会话明确显示尚未编排；原有 5G 业务仍单独展示。编排数量不代表已验证的稳定容量；详见 `lab/live/README.md`。

`frontend/workload_browser_check.py --evidence lab/unified/artifacts/<run_id>/workloads-link-restored.json` 使用隔离回归产生的证据和独立浏览器服务，检查业务表、8 种承载、调速、过期证据和手机布局。增加 `--global-fixture` 可检查 24 网关 / 384 业务的矩阵、筛选及分页（合成 UI 数据，不作为实包验收）。调速只写临时测试目录，不修改当前星座。

实时默认规模为 120 星、24 个全球网关和 384 条 TCP/UDP 业务。业务页提供城市网关矩阵、网关/协议筛选和 48 条分页；矩阵区分已编排与有新鲜实包证据的业务。节点数量和配置读取当前运行快照。配置入口见 `lab/live/README.md`。
